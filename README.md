# Небо — спільний трекер повітряних цілей

Веб-застосунок для спільного (crowdsourced) відстеження Shahed/«Герань-2»,
реактивних Shahed, крилатих і балістичних ракет: хто завгодно з будь-якої
області вносить параметри цілі (звідки пуск, напрямок, швидкість), а далі
всі учасники — з інших областей теж — можуть у реальному часі редагувати
поточну позицію, курс і список областей, куди ціль може залетіти.

**Це доповнення до офіційних систем сповіщення (ДСНС, Повітряні сили
ЗСУ, застосунок «Повітряна тривога»), а не заміна їм.** Дані вносять
самі користувачі, тому вони можуть бути неточними або застарілими —
у застосунку є текстове нагадування про це просто над мапою.

## Розгортання онлайн (не на Vercel)

**Чому не Vercel/Netlify:** це serverless-платформи — кожен запит запускає
окрему коротку функцію без спільної пам'яті й без диска, що зберігається
між викликами. Цей застосунок тримає WebSocket-з'єднання відкритими
(Flask-SocketIO) і пише в SQLite-файл — жодне з цього не працює в
serverless-моделі, звідси й `FUNCTION_INVOCATION_FAILED`. Потрібен
хостинг, що тримає ваш процес запущеним постійно.

### Render.com (рекомендовано, безкоштовно, без картки)

1. Заведіть репозиторій на GitHub і залийте туди вміст цієї папки.
2. На [render.com](https://render.com) → **New +** → **Web Service** →
   підключіть репозиторій.
3. Runtime: **Python 3**. Build Command: `pip install -r requirements.txt`.
   Start Command: `python app.py`. Instance Type: **Free**.
4. Створити. Через 2-3 хвилини застосунок буде на
   `https://<назва>.onrender.com`.

У репозиторії вже є `render.yaml` — якщо оберете "Blueprint" замість
ручного налаштування, Render підхопить ці налаштування автоматично.

**Якщо побачите `RuntimeError: The Werkzeug web server is not designed
to run in production`:** це вже виправлено в `app.py` (параметр
`allow_unsafe_werkzeug=True` у виклику `socketio.run`). Flask-SocketIO
5.x за замовчуванням відмовляється стартувати вбудований сервер на
хостингу, якщо не встановлено `eventlet`/`gevent`. Для навантаження
волонтерського моніторингу (не тисячі одночасних з'єднань) це прийнятний
компроміс; якщо застосунок виросте й знадобиться реальне масштабування —
додайте `eventlet` в `requirements.txt`, викличте `eventlet.monkey_patch()`
першим рядком `app.py` і запускайте через `gunicorn -k eventlet -w 1 app:app`.

**Важливий нюанс безкоштовного тарифу:** сервіс "засинає" після ~15 хв
без запитів і "прокидається" 30-50 секунд на перший запит після цього.
При кожному такому перезапуску контейнера SQLite-файл (`data/tracker.db`)
скидається — тобто накопичені цілі періодично зникатимуть. Для
волонтерського/тестового використання це прийнятно; якщо потрібне
довготривале збереження історії, варто або підключити платний
persistent disk на Render, або перенести дані з SQLite на зовнішню
безкоштовну базу (напр. Neon/Supabase Postgres) — можу підготувати
цей перехід окремо, якщо знадобиться.

### Fly.io (альтернатива, потребує картку для реєстрації)

Дає невеликі VM, які **не засинають** і мають справжній постійний том
(volume) для SQLite-файлу — надійніше за Render у плані збереження
даних, але для реєстрації просять прив'язати картку (з безкоштовного
ліміту гроші не знімають, якщо не перевищувати його).

## Стек

- **Бекенд:** Python, Flask + Flask-SocketIO (SQLite як сховище).
- **Фронтенд:** чистий HTML/CSS/JS (без збірки), Leaflet.js для мапи.
- **Мапа:** тайли OpenStreetMap — безкоштовно, без API-ключа.
- **Синхронізація:** WebSocket (Socket.IO) — коли хтось у Харкові додає
  поправку, її одразу бачить користувач у Львові, без перезавантаження.

## Запуск

```bash
cd shahed-tracker
python3 -m venv venv && source venv/bin/activate   # необов'язково, але бажано
pip install -r requirements.txt
python app.py
```

Відкрити у браузері: `http://localhost:5000`
(або `http://<IP-сервера>:5000`, якщо запускаєте на сервері для кількох людей).

База даних `data/tracker.db` створюється автоматично при першому запуску.

## Як користуватись

1. Вкладка **«Нова ціль»**: обираєте тип (Shahed-136 / Герань-2 /
   реактивний Shahed / крилата ракета / балістична ракета), ставите
   точку пуску (клік на мапі або вручну lat/lng), напрямок (повзунок-
   компас), приблизну швидкість (підставляється типове значення, можна
   змінити) і, за бажання, орієнтовні області, куди ціль може залетіти.
2. Після додавання ціль з'являється на мапі як анімована іконка,
   повернута в напрямку руху, з траєкторією: суцільна лінія — вже
   пройдений шлях, пунктирна — прогнозоване продовження курсу.
3. Вкладка **«Активні цілі»**: клік на ціль відкриває картку, де будь-
   хто може оновити поточну позицію (клік на мапі), скоригувати курс,
   позначити області та додати текстову поправку — це миттєво бачать
   усі інші відкриті сесії.
4. Статус цілі (у польоті / збито / влучання / втрачено спостереження)
   теж редагується в картці.

## Важливо для реального розгортання

Це робочий каркас, готовий до розширення. Що вже є, а що варто додати
перед публічним запуском для широкого кола людей:

**Вже реалізовано:**
- Сервер перевіряє тип цілі, статус і назви областей проти сталих
  «білих списків», обрізає довжину текстових полів і обмежує числа
  (курс 0–359°, швидкість тощо) — довільний JSON з фронтенду не може
  записати в базу що завгодно.
- Весь текст, який вводять користувачі (позивний, назва точки пуску,
  коментарі), виводиться на фронтенді лише через екранування
  (`escapeHtml`/`textContent`), а не напряму в HTML — це закриває
  найпростіші сценарії підстановки шкідливого коду через спільну форму.
- Простий rate-limit: не більш як один запис на зміну щосекунди з
  однієї IP-адреси (без зовнішніх залежностей).

**Чого немає й варто додати перед публічним/масштабним запуском:**
- **Модерацію й авторизацію.** Зараз редагувати може будь-хто без
  входу в систему (як у спільному документі) — зручно для швидкого
  волонтерського старту, але вразливо до вандалізму чи навмисної
  дезінформації про напрямок цілей (наприклад, хтось напише неправдиву
  область у прогнозі). Мінімум — проста автентифікація для довірених
  спостерігачів з областей; краще — модератори, що підтверджують правки
  перед публікацією.
- **Надійніший rate limiting** (Flask-Limiter + Redis) — поточний
  варіант зберігає лічильники в пам'яті одного процесу і не переживе
  перезапуск чи кілька worker-процесів gunicorn.
- **Продуктивнішу базу даних** (PostgreSQL) і **production-сервер**
  (наприклад, `gunicorn` з `eventlet`/`gevent` замість вбудованого
  Flask-сервера) під навантаженням багатьох одночасних користувачів.
- **HTTPS** через зворотний проксі (nginx/Caddy).
- Для балістичних ракет час підльоту — хвилини, тому спільне
  відстеження по областях тут малоефективне; застосунок відображає
  про це попередження у формі. Такі цілі — зона відповідальності
  офіційних систем ППО й сповіщення.

## Структура проєкту

```
shahed-tracker/
├── app.py                 # Flask + SocketIO бекенд, SQLite, REST API
├── requirements.txt
├── templates/index.html   # розмітка сторінки
└── static/
    ├── css/style.css      # стилі, анімації маркерів
    └── js/
        ├── icons.js       # SVG-іконки/кольори типів цілей
        └── app.js         # мапа, форма, список, WebSocket-логіка
```

## Області для розширення

- Заміна орієнтовних центрів областей (`OBLASTS` у `app.py`) на повні
  GeoJSON-полігони меж областей для точнішого візуального виділення.
- Push-сповіщення в браузері, коли прогнозована траєкторія цілі
  наближається до обраної користувачем області.
- Історія/архів цілей за добу для аналізу типових напрямків залітів.
